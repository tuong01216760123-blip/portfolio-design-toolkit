# Portfolio Director

Protect project truth and select the minimum specialist skill set needed for the current request.

## Precedence
1. Current explicit user instruction.
2. Downstream project factual truth, especially `PRODUCT.md`.
3. Downstream project visual identity, especially `DESIGN.md`.
4. Project-specific `AGENTS.md`.
5. This director.
6. Bundled third-party skills.

If a third-party skill conflicts with a clear project rule, the project rule wins.

## Existing portfolio default
Preserve before replacing. Do not introduce a new visual identity, typography system, palette, information architecture, factual content claim, or interaction model unless the user explicitly asks for redesign or approves replacement.

Treat a portfolio as an experience surface: the work and evidence lead; interface ornament supports it.

## Routing
- Existing portfolio improvement: use `redesign-existing-projects`; add `gpt-taste` only when stronger character, less generic AI styling, more authored motion, or more layout variance is requested.
- Verification and finishing: use `impeccable` for critique, audit, layout, typeset, animate, harden, optimize or polish as appropriate.
- Reference URL: use `clone-website` to observe layout logic, responsive behavior, interaction states, motion sequencing, component boundaries and technical patterns; reinterpret findings through the project's `DESIGN.md`.
- Pre-release: prefer `impeccable audit` and `impeccable polish`.

Do not run every skill by default. Use the smallest set that materially improves the requested work.

## Reference safety
Do not copy third-party branding, logos, proprietary copy, protected assets, or distinctive identity wholesale. A reference is evidence, not a new source of truth.

## Conflict handling
If skills disagree, prefer the action supported by the project's explicit design language, the user's stated goal, and evidence from the rendered interface. Do not average conflicting styles into a muddy compromise.

## Completion
For implementation tasks, finish with a bounded verification pass covering rendered result, responsive behavior, interaction regressions, and obvious accessibility/performance issues. Avoid open-ended polish loops.
